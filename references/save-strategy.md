# 省钱策略详解（save-strategy）

本参考供 Skill 调用时遵循，解释「为什么这么比价」「券有哪些类型」「怎么凑最省」。

## 1. 券的类型（来自麦当劳 MCP）

| 类型 | 来源 Tool | 特点 |
|---|---|---|
| 麦麦省可领券 | `available-coupons` / `auto-bind-coupons` | 主动领取，常是满减/买赠，有领取上限 |
| 账户已有券 | `query-my-coupons` | 历史领取 + 活动发放，注意有效期 |
| 门店专属券 | `query-store-coupons` | 绑定具体 `storeId`，与外送/到店门店相关，**最容易被忽略** |
| 活动券 | `campaign-calendar` 联动 | 限时大促（半价盒、会员日），需踩时间点 |

## 2. 比价核心：`calculate-price` 是唯一真相

不要凭券面额脑补——同一张「满减券」在不同清单下的实际优惠不同（是否踩中门槛）。
必须对同一清单用不同券组合各跑一次 `calculate-price`，取**应付总价最低**者。

## 3. 拆单策略

当存在多张「满减券」且单张门槛较低时，把清单拆成两单可能比一单更省：
- 例：清单 ¥60，有「满30减8」×2。一单用 1 张省 ¥8；拆两单各用 1 张省 ¥16。
- 但拆单会增加配送费/操作成本，需 `calculate-price` 验证「省下的 > 多出的配送费」才建议。

## 4. 时效与被忽略的券

- `query-my-coupons` 中临期券优先用；`campaign-calendar` 提示的大促可「等一天更省」。
- 用户常犯：只用自己的券，忘了 `query-store-coupons` 的门店券——Skill 必须两者都查。

## 5. 健康与省钱的平衡

`list-nutrition-foods` 给出热量/蛋白/钠。在「最省」与「相对健康」冲突时，先给最省方案，
再附「+¥X 换成低钠/高蛋白」的备选，让用户选，不替用户做营养决策。

## 6. 反作弊与合规

- 不刷券、不绕过限领；`auto-bind-coupons` 仅领官方开放的可领券。
- 不存储任何 Token / 个人信息。
- 所有数值以 MCP 实时返回为准，不在 Skill 内硬编码价格。
